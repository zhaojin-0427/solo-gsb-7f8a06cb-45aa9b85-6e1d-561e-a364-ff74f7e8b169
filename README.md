# 录音片段定位（Audio Clip Locator）

本地网页工具，包含两个功能：

1. **片段定位**：上传一段**参考录音**和一段**待找片段**，在参考录音中定位片段出现的位置，
   在波形上标出命中区间，并可从命中处试听；唯一命中时还能带上下文导出精确裁剪的命中片段 WAV。
2. **片段顺序核验**：上传一段**参考录音**与按预期顺序排列的 **2～5 段片段**，
   核验它们能否在参考录音中**按该顺序、互不重叠**地各出现一次；唯一链会列出各段起止毫秒与
   相邻空档并在参考波形上标出，无完整链时判定顺序不成立，存在近总分的不同链时提示多解。

- 后端：Python + FastAPI + NumPy + SciPy
- 前端：原生 HTML / CSS / JavaScript（无任何前端依赖，波形用 Canvas 绘制）
- 匹配算法：归一化互相关（NCC），用 FFT 卷积一次算出所有候选起点，**不做逐位置逐采样点遍历**

## 一条命令启动

```bash
docker compose up --build
```

启动后在浏览器访问：**http://localhost:8000**

（端口映射为 `8000:8000`，如需修改请编辑 `docker-compose.yml` 中的 `ports`。）

也可以不用 Compose，纯 Docker：

```bash
docker build -t audio-locator .
docker run --rm -p 8000:8000 audio-locator
```

本地开发（不用 Docker）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 打开 http://localhost:8000
```

## 输入要求

| 项目 | 参考录音 | 待找片段 |
| --- | --- | --- |
| 时长 | 1 ～ 30 秒 | 0.2 ～ 5 秒（且须短于参考录音） |
| 格式 | 未压缩 PCM WAV（16 位） | 同左 |
| 声道 | 单声道或双声道 | 同左 |
| 采样率 | 8 ～ 48 kHz | 8 ～ 48 kHz，**可与参考录音不同** |

片段应来自参考录音，但允许**不同的采样率**和**不同的整体音量**。
格式或时长不合要求时，接口返回 400 并在页面上给出具体原因
（非 WAV、非 16 位、声道数、采样率越界、时长越界等分别提示）。

**片段顺序核验**额外要求：片段数量 **2～5 段**，上传时按预期顺序排列；
每段同样为 16 位 PCM WAV、0.2～5 秒、8～48 kHz，可与参考录音及彼此采样率不同，
且每段都须短于参考录音。各段在公共采样率时间轴上比较位置，因此采样率互不相同也能核验。

## 处理流程

1. **校验与解码**：检查 WAV 头（PCM、16 位、声道数、采样率）与时长。
2. **转单声道**：双声道取左右均值。
3. **统一重采样**：用 `scipy.signal.resample_poly`（多相滤波，抗混叠）把两路信号
   重采样到两者中**较低**的采样率——片段中不存在的高频无法参与匹配，
   向高采样率对齐只会引入失配能量。
4. **去直流偏移**：两路信号各自减去均值。
5. **归一化互相关（FFT 加速）**：
   - 分子 `ref ⋆ clip` 与分母所需的滑动窗口能量均用 `scipy.signal.fftconvolve`
     一次算完，复杂度 O(N log N)，不逐位置遍历；
   - 每个候选起点得到 [-1, 1] 的相关系数，对整体音量变化天然不变。
6. **判定**：
   - 任一路信号峰值低于约 -60 dBFS → 判定**近乎静音，无法定位**；
   - 最高得分 < 0.8 → **无法定位**（返回实际最高分）；
   - 存在 ≥ 2 个起点，彼此相距 ≥ 0.25 秒、得分均 ≥ 0.8 且与最高分相差 ≤ 0.02
     → **定位不唯一**，列出全部候选；
   - 否则 → **唯一命中**，给出起止时间（毫秒精度）与得分。

### 片段顺序核验

1. 对 2～5 段片段**分别**执行与单片段定位相同的 WAV 校验、重采样、去直流与 NCC 计算；
   各段候选统一换算到「参考录音与所有片段的**最低公共采样率**」这一时间轴上比较位置。
2. **候选选取**：从得分不低于 **0.8** 的起点按**得分降序贪心**选取，同段候选相隔至少
   **0.25 秒**。与单片段定位不同，**保留全部 ≥ 0.8 的候选（含较低分候选）**，
   因为较低分候选可能是组成全局顺序链的唯一选择。
3. **拼链**：用动态规划求「每段各取一处、按输入顺序排列、互不重叠（允许首尾相接）」的
   完整链，以**未舍入得分之和**最高者为结果；段内每个候选只保留以它结尾的最高两条不同链，
   因此可同时得到与最高链不同的次优链。
4. **结论**：
   - 任一段无 ≥ 0.8 候选（或近静音）→ **顺序不成立**，指出失败的段与原因；
   - 拼不出完整链（片段在参考中虽有命中，但无法按输入顺序互不重叠排列）→ **顺序不成立**；
   - 另一条不同链的总分与最高总分之差 ≤ **0.02** → **多解提示**，同时列出两条链；
   - 否则 → **顺序成立（唯一链）**，给出各段起止毫秒、相邻空档（毫秒）、各段得分与总分。

## 页面功能

- 唯一命中：显示起止时间（`mm:ss.mmm`）与相关得分；
- 导出命中片段：唯一命中后可设置命中点**前后各 0～2 秒**上下文（步长 100 ms），
  服务端按**原始参考 WAV 的采样率、声道与 16 位 PCM 精确裁剪**（直接切 PCM、
  不重采样、不重新编码），超出参考录音边界时自动收紧，并在页面上显示**实际起止毫秒**，
  导出的 WAV 直接触发浏览器下载；定位不唯一、无法定位或范围无效时不生成文件，
  原定位提示保留；
- 定位不唯一：列出所有候选区间与得分，每个候选都可单独试听；
- 无法定位 / 输入不合要求：显示明确原因；
- 参考波形上高亮命中（候选）区间，点击波形可跳转播放位置，
  支持「从命中处试听」「从头播放」，播放时显示播放头。
- **片段顺序核验**模块复用同一份参考录音，另按顺序选择 2～5 段片段（可增删）；
  顺序成立时在独立的参考波形上按段序号标注唯一链的各区间，多解时用蓝色实线标出
  最高链、琥珀色虚线标出另一条链，顺序不成立时说明原因；点击链表格中的任意行可从
  该段起点试听，原始的单片段定位与导出功能保持不变。

## 接口

### `POST /api/locate`

`multipart/form-data`，字段：`reference`（参考录音 WAV）、`clip`（待找片段 WAV）。

成功（200）返回示例：

```json
{
  "status": "located",
  "sample_rate": 16000,
  "best_score": 0.9987,
  "candidates": [{ "start_s": 3.25, "end_s": 4.45, "score": 0.9987 }],
  "clip_duration_s": 1.2,
  "reference": { "duration_s": 10.0, "sample_rate": 44100, "channels": 2 },
  "clip": { "duration_s": 1.2, "sample_rate": 16000, "channels": 1 }
}
```

`status` 取值：`located`（唯一命中）/ `ambiguous`（定位不唯一，含多个候选）/
`not_found`（无法定位，`reason` 为 `silence` 或 `low_score`）。

输入不合要求返回 `400`，`detail` 为具体中文错误信息。

### `POST /api/export`

`multipart/form-data`，字段：

| 字段 | 说明 |
| --- | --- |
| `reference` | 参考录音 WAV（同 `/api/locate` 的输入约束） |
| `clip` | 待找片段 WAV |
| `pre_ms` | 命中点前上下文（毫秒），整数，`0～2000`，步长 `100`，默认 `0` |
| `post_ms` | 命中点后上下文（毫秒），整数，`0～2000`，步长 `100`，默认 `0` |

服务端会**重新执行一次定位**（接口无状态）：仅当结果为唯一命中（`located`）时，
才按原始参考 WAV 的采样率、声道、16 位 PCM 直接裁剪命中区间加上下文，
返回 `200` 与 `audio/wav` 附件（`Content-Disposition: attachment`），
并通过响应头回传收紧后的实际范围：

- `X-Export-Start-Ms`：实际起点（毫秒）
- `X-Export-End-Ms`：实际终点（毫秒）

返回示例（响应头节选）：

```
Content-Type: audio/wav
Content-Disposition: attachment; filename="hit_2750-5150ms.wav"
X-Export-Start-Ms: 2750
X-Export-End-Ms: 5150
```

错误情况：

- `pre_ms` / `post_ms` 越界或不是 100 的整数倍、文件不合要求 → `400`；
- 定位不唯一或无法定位 → `409`，`detail` 为具体原因，**不生成文件**。

### `POST /api/sequence`

片段顺序核验。`multipart/form-data`，字段：

| 字段 | 说明 |
| --- | --- |
| `reference` | 参考录音 WAV（同 `/api/locate` 的输入约束：1～30 秒） |
| `clips` | **按预期顺序排列**的片段 WAV，以同名字段 `clips` 重复上传 **2～5 次**；每段 0.2～5 秒且短于参考录音；字段先后顺序即片段顺序 |

每段保留所有得分 ≥ 0.8 的候选（同段候选相隔 ≥ 0.25 秒，含较低分候选），
再以未舍入得分之和最高的完整链为结果。HTTP 层面只要输入合法即返回 `200`，
核验结论放在 `status` 字段：`verified`（顺序成立，唯一链）/
`ambiguous`（多解，含 `best_chain` 与 `alternative_chain`）/
`no_chain`（顺序不成立，`reason` 为 `order_not_satisfied` 或
`segment_not_found`）。

`verified` 返回示例（3 段）：

```json
{
  "status": "verified",
  "sample_rate": 16000,
  "segment_count": 3,
  "reference": { "duration_s": 10.0, "sample_rate": 16000, "channels": 1 },
  "segments_info": [
    { "duration_s": 0.5, "sample_rate": 16000, "channels": 1 }
  ],
  "message": "各段可按输入顺序组成唯一的完整链，顺序成立",
  "chain": {
    "total_score": 2.9994,
    "analysis_sample_rate": 16000,
    "segments": [
      { "segment": 1, "start_ms": 1000, "end_ms": 1500,
        "start_s": 1.0, "end_s": 1.5, "score": 0.9999,
        "gap_before_ms": null },
      { "segment": 2, "start_ms": 4000, "end_ms": 4500,
        "start_s": 4.0, "end_s": 4.5, "score": 0.9998,
        "gap_before_ms": 2500 },
      { "segment": 3, "start_ms": 7000, "end_ms": 7500,
        "start_s": 7.0, "end_s": 7.5, "score": 0.9997,
        "gap_before_ms": 2500 }
    ]
  }
}
```

`ambiguous` 时把 `chain` 换成 `best_chain` / `alternative_chain`（结构相同，
均含各段起止毫秒与相邻空档），并在 `message` 中给出两条链的总分与差值；
`no_chain` 时无链字段，`segment_not_found` 另带 `failed_segments`
（段序号、`reason`、`best_score`）。

错误情况：片段数量不在 2～5、缺少 `clips`、任一段非 WAV / 位深或采样率越界 /
时长越界 / 不短于参考录音 → `400`，`detail` 为具体中文错误信息（片段标签带序号）。

另有 `GET /api/health` 健康检查。

```bash
pip install -r requirements.txt httpx
python3 tests/selftest.py
```

覆盖：异采样率/异音量/含直流偏移的唯一命中、低分无法定位、近静音、
定位不唯一（含 0.25 秒间隔边界）、全部格式与时长校验分支；
命中片段导出：位精确裁剪、实际起止毫秒、开头/结尾越界收紧、
双声道保持、定位不唯一/失败返回 409、上下文非法返回 400；
以及片段顺序核验：唯一链起止毫秒与相邻空档（含首尾相接空档 0）、逆序判定
顺序不成立、多解两条链总分差 ≤ 0.02、较低分候选（仍 ≥ 0.8）被保留并成为
唯一可成链选择、含低分/静音片段时指出失败段，以及片段数量、字段缺失、
非 WAV、时长越界等 HTTP 400 分支。
